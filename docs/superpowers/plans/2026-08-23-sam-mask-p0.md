# SAM Mask P0 Data Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in, backward-compatible SAM mask cache and audit pipeline without changing the main model, validation, inference, or legacy dataset behavior.

**Architecture:** New focused utilities own cache validation/shared-mask preparation and GT-node auditing. `datasets/RS_ST.py` only coordinates optional loading and synchronized augmentation, while its default four-item return remains unchanged. Graph data remains outside `ChangeDetection` and the existing optimizer/checkpoint state.

**Tech Stack:** Python 3, NumPy, PyTorch, pytest/unittest, existing torchvision/skimage stack; no new dependencies.

## Global Constraints

- Preserve the current Landsat default and SECOND dynamic class configuration.
- Do not implement a SAM mask generator, EdgeNet, GAT, prototypes, or graph training.
- Do not change `ChangeDetection.forward`, validation, inference, or existing checkpoint payloads.
- Cache loading must use `numpy.load(..., allow_pickle=False)`.
- Existing dataset callers must continue receiving exactly four values unless graph data is explicitly enabled.
- All production behavior is implemented test-first.
